# M5: queries, connected operations and observability

## Acceptance evidence

- Indexed, allowlisted financial/operator queries; bounded keyset traversal with resource/filter validation and generation pinning. Comparison/provenance pages have separate cursors. Existing M4 contracts remain covered.
- Bearer and expiring browser sessions; hashed session storage, origin/CSRF rejection, token-free error responses, source autoescaping and CSP. API documentation assets are locally vendored and integrity-verified.
- Concurrent same-key submissions converge to one durable request/job/outbox; changed bodies conflict. Worker actions complete comparison, backfill, cancellation, linked redrive and offline replay, with auditable results. An expired replay worker cannot write a generation.
- SQL-based queue/attempt/retry/freshness metrics distinguish scheduled retries and Redis delivery state. Controlled eligible backlog exceeds the lag threshold; Promtool fixtures verify alert firing and quiet offline conditions.
- One trace connects a stub SEC fetch, preserved source and projection commit. Failed attempts retain their trace ID and error status. A blocked exporter with a full queue does not prevent a worker's successful SQL commit.
- Browser checks cover the connected palette/layout, comparisons, provenance, source inventory, sign-in boundary, mobile layout and local API docs. Operator mutation flows are exercised against real PostgreSQL/Redis/S3 by integration tests.
- Local upgrade to 0006 was preceded by a PostgreSQL dump in ignored `.local/backups/secrecon-pre-m5.dump`; readiness reports 0006. Raw data and existing histories were retained.
