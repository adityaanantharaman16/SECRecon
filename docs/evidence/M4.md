# M4: reconciliation and schema evolution

Implemented explicit snapshot-bound comparisons, automatic candidate evidence, immutable comparison history, structured schema diagnostics and versioned offline reprocessing. Migration 0005 preserves existing data and adds the supporting indexes and tables. See ADR 0003 for exact contracts and limitations.

## Acceptance scenarios

- Changed and unchanged values, original-only and amendment-only observations, conflicting values, and mismatched concept/unit/instant/duration/reporting periods.
- Missing amendment facts yield incomplete coverage; no absent fact is labeled deleted or converted to zero.
- Multiple plausible originals remain ambiguous. Explicit pair comparison remains available without changing that link.
- Late older source processing cannot replace the latest selected snapshot. Concurrent identical explicit comparisons converge to one immutable run. Later revisions retain earlier runs.
- Real Robinhood 2025 10-K/10-K/A observations compare unchanged, with both original documents and source snapshots exposed. Replay rebuilds the same canonical comparison output.
- Optional-field additions generate diagnostics without breaking extraction. A required numeric type change is quarantined atomically with a JSON path and code.
- V2 accepts the deliberately simulated numeric-string change, retains v1 quarantine evidence, rebuilds separately and produces a generation report. Recorded source behavior remains supported under both parsers. Unsupported/unsafe numeric shapes are rejected.
- Parser changes during preparation reject the stale commit and are classified for retry. Replay resumes only with its original parser/comparison version pair.
- Exact decimal subtraction remains correct for large values, tiny fractions and very different scales.
- Empty-database reconstruction and an upgrade from 0004 with an existing numeric fact and quarantine record are exercised. Legacy replay records are identified explicitly.

## Validation record

The final complete M4 suite passed **79 tests** with **90.75%** domain/job branch-inclusive coverage in 95.36 seconds. Audit follow-ups include a previous-schema migration case and a wider decimal-scale case. Lint, formatting and strict typing also passed as mandatory parts of the full gate. Existing upstream Starlette/httpx deprecation warnings remain nonfatal. Hosted results are recorded in GitHub Actions.

The existing local runtime upgraded from 0004 to 0005 successfully. Readiness reports 0005; refreshing candidate links and explicitly comparing the seeded original/amendment both succeeded. The read-only API exposes that immutable result.

Primary command: `docker compose -p secrecon-m4-final -f compose.yaml -f compose.test.yaml run --build --rm test`. Logs are ignored under `.local/m4-final-gate.log` and `.local/m4-audit-gate.log`.

The audit found and resolved missing snapshot indexes, a duplicate pytest module name, Decimal exponent-alignment precision, and the need to distinguish pre-M4 replay records. It also separated generation comparison persistence from the CLI, pinned replay comparison versions, and added discovery-source IDs to candidate evidence.

## Frontend concept

`demo/` contains six navigable screens, three comparison scenarios, a provenance drawer, filing search, result filtering, simulated linked redrive, simulated replay and a seven-step walkthrough. All data and actions are labeled fictional. Browser checks cover desktop and 390-pixel layouts, comparison coverage messaging, preservation of dead-letter history after redrive, replay completion, and the tour. This is a static preview, not M5 completion.

## Remaining boundaries

No public deployment, real admin web actions, authentication, full-text XBRL extraction, manual-link override, or M5 telemetry is claimed. Comparisons and generation reports are bounded by the project's company-focused scope; API cursor pagination and broad load testing remain M5/M6. No new SEC requests were required for M4.
